## Assertion A11C — case-insensitive injectivity, proved on a planted pair

HubSpot lowercases a property name silently, so two names differing only in case are ONE property and the second create fails or overwrites — permanently, on a portal that does not free a name.

- **The plant:** `irs433d_date1` / `irs433d_Date1` — differing only in case. The comparator **caught it**.
- **The conforming pair:** `irs433d_date1` / `irs433d_date2` — not flagged, correctly. A comparator that flags everything is [R-10] and gets turned off.
- **The real population:** 78 derived names, 78 distinct under lowercasing. 0 collision(s).

The plant is not decoration. A11 forces every name to lower-snake-case, so the real population **cannot** contain a case-differing pair, and an assertion reporting PASS over a population that cannot be non-empty is the vacuous guard this engine has removed a dozen of. **This form is where it would have bitten:** `433d.map.json` carries `_key_overrides` because `Date1` and `Date2` collided with `date1` and `date2` at map level, one layer below this one.
